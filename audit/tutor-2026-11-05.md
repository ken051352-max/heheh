# Roadmap tutor: research, implementation and verification

Date: **2026-11-05**. Scope: an optional tutor for the existing roadmap, time management and private evidence tracking, installed for Codex and OpenCode. This extends the completed curriculum work; it is not another full curriculum audit. Historical validation counts remain historical.

## Decisions and inspected sources

- **Use original instructions informed by existing tutors.** Inspected [hammer's teaching skill](https://raw.githubusercontent.com/SebastianElvis/hammer/main/skills/teach/SKILL.md), [state editing](https://raw.githubusercontent.com/SebastianElvis/hammer/main/skills/teach/references/state-editing-protocol.md) and [review buckets](https://raw.githubusercontent.com/SebastianElvis/hammer/main/skills/teach/references/review-buckets.md). Adopt the idea of reading persistent state before teaching and storing it outside the skill. Do not adopt fixed mastery thresholds or retry limits as scientific requirements. GitHub metadata reported MIT licensing; no upstream code or prompts were copied.
- **Use graduated help with accurate evidence.** Inspected [socratic-tutor's prompt](https://raw.githubusercontent.com/JrKrishh/socratic-tutor/main/lib/systemPrompt.ts) and [session persistence](https://raw.githubusercontent.com/JrKrishh/socratic-tutor/main/lib/session.ts). Its nullable duration and distinction between demonstrated insights and assistance informed our record. Browser-local persistence would not share state across our two tools; use a checkout-local file. A rigid questions-only policy does not fit direct explanation requests. GitHub metadata reported MIT licensing; implementation here is original.
- **Ground teaching in current source material.** Inspected [ProjectSchola's skill](https://raw.githubusercontent.com/OJ102/ProjectSchola/main/skills/teach/SKILL.md) and [license](https://raw.githubusercontent.com/OJ102/ProjectSchola/main/LICENSE). Source-based lessons and prerequisite checks are useful patterns. Its license excludes inherited material from an unlicensed upstream project; no prompts or code were copied. Repository availability is not evidence of tutoring effectiveness.
- **Plan, observe and adapt.** [Panadero (2017)](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2017.00422/full) reviews self-regulated learning models; abstract, introduction, methods and cyclical-model discussion were inspected. It supports the planning/monitoring/reflection framing, not a particular timer length or this tutor's efficacy. The existing six-week pilot remains the reflection process.
- **Include retrieval and revisits without a magic interval.** The public abstract/conclusions of [Dunlosky et al. (2013)](https://journals.sagepub.com/doi/10.1177/1529100612453266) support practice testing and distributed practice. Full article access was restricted. No universal review interval or guaranteed programming transfer is claimed. [Google's LearnLM prompt guide](https://services.google.com/fh/files/misc/learnlm_prompt_guide.pdf) supplies practitioner guidance about active participation, manageable chunks and reflection, not independent efficacy evidence.
- **Install against current tool documentation and actual discovery.** Fetched official [Codex skills](https://developers.openai.com/codex/skills) and [AGENTS.md guidance](https://developers.openai.com/codex/guides/agents-md). Current user discovery includes `.agents/skills`; local older skill-authoring guidance suggested `.codex/skills`. Actual Codex prompt inspection resolves this mismatch in favor of the discoverable `.agents` location. Root `AGENTS.md` routes tutoring requests; singular `agent.md` is a learner guide.
- **Use OpenCode v2 syntax.** Fetched [v2 skills](https://opencode.ai/v2/docs/skills/) and [v2 agents](https://opencode.ai/v2/docs/agents/). The installed version is 2.2.5: skill calls use `id`, and the primary agent inherits model/permissions. Do not use deprecated V1 `tools`/`permission` configuration. The native skill copy takes precedence over shared compatibility discovery for the same ID; the installer synchronizes both copies.

Exa and Context7 were available. An Exa request for a guessed v2 server-documentation URL failed with `CRAWL_NOT_FOUND`; it did not establish that the server/API feature was absent. Context7 then supplied the [actual skill API source](https://github.com/anomalyco/opencode/blob/dev/packages/protocol/src/groups/skill.ts) and CLI operation. Runtime `GET /api/skill` verified the installed behavior. An earlier `/doc` probe returned HTML, not an OpenAPI schema. These probes were not counted as successful skill discovery.

## Implementation and plan refinements

The skill reads the manifest, current milestone, readiness criteria and relevant project brief on demand. It offers explanations, hints or worked examples according to the request; narrow independent checks remain separate from assistance. Time budgets include buffer, actual time is nullable, review dates are suggestions, and a missed week does not create hours owed.

The standard-library helper stores sessions and the current plan in ignored `study-private/tutor/`. It validates module/subset IDs and input shape, refuses overscheduling and conflicting duplicate records, locks writes, preserves the previous state and atomically replaces files. It never derives module completion or measures learning effectiveness. The installer copies only an explicit file list, preflights conflicts and backs up changed destination files with `--update`. It does not copy private logs or change providers/permissions.

Substantial implementation adjustments:

1. **Current tool versions over remembered formats:** chose Codex `.agents` discovery and OpenCode v2 agent syntax after reading current documentation and inspecting installed versions.
2. **Verified startup rather than assumed discovery:** early isolated OpenCode API requests returned only built-ins. This initially suggested a directory issue, so a native copy was added. A later persistent-service request after startup returned the native tutor. This does not prove the shared directory is unsupported; the installed native path is what was actually verified. Retain synchronized copies at the documented locations.
3. **Direct explanation without a forced quiz:** an independent simulated teaching pass identified ambiguity in “after a solution, offer a transfer problem.” Clarified that an explanation-only request should not receive an unwanted quiz; transfer practice comes when the learner is ready.
4. **Repair the unusable local CLI:** the installed `@opencode/cli` 2.2.5 launcher target was a 229-byte postinstall placeholder. Inspected package metadata/postinstall behavior, installed the matching official Windows x64 baseline package with scripts disabled, verified its executable signature/version and replaced only the placeholder binary. Backed up the placeholder locally. `opencode v2.2.5` now executes. Provider files and credentials were not changed.

## Limits

No six-week learner trial occurred, no study duration was inferred, and no production learner outcomes are claimed. No calendar or notification service was configured. No paid model session was needed for installation/discovery tests. The installer is exercised with temporary homes on this Windows machine; Linux CI is configured but not claimed to have run for this local branch. Local records are Git-ignored, not encrypted or automatically synchronized across devices. A previous-state backup is not a complete history/backup service. Invalid records require review rather than automatic reset. The helper's initial profile is fixed to India time and an undecided role; it has no profile-edit command. The tutor should honor corrected learner context and explicitly review a needed profile change instead of treating defaults as permanent facts.
