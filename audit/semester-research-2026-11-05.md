# First-semester and readiness research — 2026-11-05

Scope: the new semester/readiness guides, existing Week 0 and first-30-days instructions, and M0–M8b module integration. This record describes current source inspection and design decisions; it does not rewrite historical audit results or claim a student trial. The broader [learning-experience research](learning-experience-research-2026-11-05.md) records independent book comparisons, learning-design sources and additional artifact checks.

## Decisions and changes to the initial approach

1. **Use the same lecture spine from the first task.** Existing Week 0 required three Scrimba projects before switching to CS50P. Exa retrieval of the Scrimba course returned `CRAWL_EMPTY_CONTENT`; direct HTTP retrieval then succeeded and official metadata/launch material describes the course as free (details below). The new required route starts with a small portion of CS50P Lecture 0 and continues it in Week 1 to avoid overlapping course assignments. This is a continuity/scope judgment, not a finding that Scrimba is paid or unavailable. Scrimba remains an optional alternative and previous work remains valid evidence. No repeated onboarding is required.
2. **Budget the semester around one learning task at a time.** The old opening weeks combined full CS50 problem sets, extra Exercism quotas, multiple math activities and a project under a 5–7-hour label. There was no measured basis for fitting all of that into the budget. The single semester schedule now uses one small original artifact and a readiness check per milestone; course problem sets supply optional targeted practice unless the learner separately pursues that course's certificate. This is a scope/design judgment, not a measured efficiency claim.
3. **Reuse the Weather artifact for files and API failure handling.** The competing four-phase table required another file-I/O app. The semester now develops one bounded capstone, with testing/files before cache/API behavior. Optional depth remains available; full M1 evidence still precedes dependent M4/M7/M8a work.
4. **Conditional SQL, no first-semester framework stack.** Two final milestones introduce queries and joins only if M1 evidence exists. Integration review found the project kit's full assessment also required ingestion, quarantine/replay, transaction rollback and plan analysis, which would overfill two introductory weeks. The semester therefore uses a supplied clean-data query sandbox and read-only query/reconciliation evidence. Those implementation stages move after CS50 SQL Designing/Writing in subsequent M8a work. The SQLite fixture is a preview, not full M8a completion. Full M8a retains migrations, constraints, windows and measured PostgreSQL plans; a decision table/chart may replace an ornamental dashboard. M7's full data-quality pipeline/figures remain separate outcomes.
5. **Assess capability without a universal score or AI permission badge.** The former `three-check-gate` anchor remains compatible, but points to reading, debugging and explaining a changed example. The new guide separates supported learning from independent demonstration. No score decides who belongs in the subject, and maths placement remains optional.

## Limits and maintenance

The 5–7-hour budget, two buffer weeks and 16-milestone shape are planning assumptions. No six-week study run, retention improvement or student completion rate was observed. The [study pilot](../guides/study-pilot.md) is a usable process for collecting that evidence later. Readiness examples have concrete expected behaviors, but are lightweight curriculum checks, not psychometrically validated exams. Current student circumstances should change pace and selected depth.

Stable module IDs, manifest prerequisites and explicit anchors remain intact. New guides distinguish a narrow check/preview from full-module completion. Existing topic depth is retained behind collapsible sections; required outcomes and core projects remain visible. Historical diagnostic tables remain explicitly non-operational.
